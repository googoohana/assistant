# GGHN 콘텐츠 비서

GGHN의 브랜드 정의서를 영혼으로 삼는, 한 사람을 위한 콘텐츠 작업 비서다. 단순 챗봇이 아니라 **발굴 → 초안 → 검수**의 3단 워크플로우 도구다.

이 문서는 **코딩을 잘 모르는 사람**이 처음부터 끝까지 따라할 수 있게 쓰여졌다. 각 단계마다 "왜 이걸 하는지"가 함께 있다.

---

## 1. 처음 세팅 — 1시간이면 끝

### 1-1. GitHub 저장소 만들기

> **왜?** GitHub Pages는 정적 웹사이트를 무료로 띄워주는 서비스다. 우리 비서는 빌드 도구 없이 HTML 한 장으로 작동하므로 GitHub Pages가 딱 맞다.

1. github.com에 로그인 → 우상단 `+` → **New repository**
2. 이름은 `gghn-assistant` (또는 원하는 이름) — 이 이름이 URL에 들어간다
3. **Public**으로 설정 (Pages는 Public이어야 무료)
4. `Add a README file` 체크 → **Create repository**

### 1-2. 이 폴더의 파일들을 저장소에 올리기

내 컴퓨터에서 이 폴더(`gghn-assistant/`) 안의 모든 것을 GitHub에 올려야 한다.

**방법 A: 웹에서 드래그 (가장 쉬움)**

1. 방금 만든 저장소 페이지에서 `Add file` → `Upload files`
2. 이 폴더의 모든 파일/폴더를 드래그
3. 제일 아래로 내려가 `Commit changes`

**방법 B: 명령어 (조금 익숙해지면)**

```bash
git clone https://github.com/내아이디/gghn-assistant.git
# 위에서 클론한 폴더에 이 파일들을 복사한 뒤
git add .
git commit -m "초기 세팅"
git push
```

> **왜 git을 배우면 좋은가?** 학습 로그(memory/log.json)를 누적하려면 어차피 git push가 필요하다. 처음엔 웹 드래그로 시작하고, 익숙해지면 명령어로 넘어가도 된다.

### 1-3. GitHub Pages 활성화

1. 저장소 페이지 상단 메뉴에서 **Settings** 클릭
2. 왼쪽 사이드바에서 **Pages** 클릭
3. `Source`를 **Deploy from a branch**로 두고, 브랜치는 **main**, 폴더는 **/(root)** 선택 → **Save**
4. 1~2분 기다리면 페이지 상단에 `Your site is live at https://내아이디.github.io/gghn-assistant/` 같은 URL이 뜬다

> **왜 1~2분?** GitHub이 사이트를 빌드하고 전 세계 서버에 배포하는 시간이다. 이후 파일을 push할 때마다 자동으로 다시 빌드된다.

오류 없이 응답이 흘러나오면 성공이다.

## 2. 브랜드 정의서 수정하는 법

> **이게 이 비서의 핵심이다.** 정의서가 곧 비서의 영혼이라, 정의서만 고치면 비서 성격이 바뀐다.

1. GitHub 저장소에서 `config/brand.md` 파일 클릭
2. 우상단 연필(✏) 아이콘 클릭 → 편집 모드
3. 본문 수정. 단, **첫 줄의 frontmatter는 형식을 유지**해야 한다:

```
---
version: v1.2     ← 버전을 올려라. 이게 UI 하단에 자동 표시됨
updated: 2026-05-01
---
```

4. 페이지 아래로 내려가 `Commit changes` (커밋 메시지: "정의서 v1.2 — XX 항목 수정" 식으로)
5. 1~2분 후 비서 페이지를 새로고침. 또는 `⚙ 설정 → config 새로고침` 클릭.

> **왜 버전을 올리는가?** 나중에 비서가 어떤 버전의 정의서로 답했는지 추적할 수 있고, 한 달 뒤 정의서가 어떻게 진화했는지 본인이 알아보기 위해서다.

## 3. 워크플로우 추가/수정하는 법

### 기존 워크플로우 수정 (예: 검수 기준 추가)

1. `config/workflows/3-review.md` 편집 → 새 점검 항목 추가
2. Commit → 페이지 새로고침. 끝.

> HTML이나 JS는 건드릴 필요가 **전혀 없다.** 비서는 매번 fetch로 최신 파일을 읽는다.

### 새 워크플로우 추가 (예: 4번째 탭 "기획" 추가)

워크플로우를 4개로 늘리려면 두 군데를 만져야 한다.

**1) `config/workflows/4-plan.md` 새로 만들기**
   - 기존 1, 2, 3번 파일과 같은 구조로 (너의 일 / 출력 형식 / 금기)

**2) `index.html`에서 탭 한 줄 추가**
   - `<button class="tab" data-workflow="4-plan" onclick="switchTab(this)">기획</button>`
   - `state.config.workflows`를 채우는 fetch에 `'config/workflows/4-plan.md'` 추가
   - `switchTab` 함수 안의 if/else에 4-plan 분기 추가

> **왜 1)만으론 안 되는가?** 탭 UI는 HTML에 박혀 있어서다. 만약 탭 추가가 잦다면, 다음 버전에서 탭도 config에서 자동 생성하도록 개조할 수 있다(숙제로 두자).

## 4. 점진 학습 로그 검토하는 법

비서는 매 호출 시 `memory/log.json`의 **최근 7개 lesson**을 시스템 프롬프트에 자동으로 첨부한다. 그래서 로그를 잘 쌓으면 비서가 점점 너의 결을 따라간다.

### 누적하는 방법 (정석)

1. 비서가 응답을 준 후 **📝 이번 결과 기록하기** 클릭
2. 짧게 메모 (좋았던 점 / 안 맞았던 점 / 한 줄 교훈)
3. `저장` — 일단 브라우저에 누적됨
4. 진짜로 누적하려면 **⬇ log.json 다운로드** 클릭
5. 다운받은 `log.json`을 GitHub 저장소의 `memory/log.json`에 **덮어쓰기** (저장소에서 파일 클릭 → 연필 → 내용 전체 교체 → Commit)
6. 1~2분 후 비서가 새 log를 읽기 시작

### 검토하는 방법

`memory/log.json`을 GitHub에서 직접 열어보면 시간순으로 lesson이 쌓여 있다. 한 달에 한 번쯤 훑어보면, 자기가 어떤 결을 좋아하고 어떤 걸 거절해 왔는지 패턴이 보인다.

> **왜 이게 중요한가?** 정의서가 "공식 자아"라면, log.json은 "실전 자아"다. 시간이 갈수록 둘이 어떻게 일치하거나 어긋나는지가 GGHN의 진화 그 자체다.

## 5. 비용 가이드

**Gemini API 무료 티어** 기준이라 별도 비용이 없다.

### 무료 한도 (신용카드 불필요)

| 모델 | 분당 요청 | 하루 요청 | 비용 |
|------|----------|----------|------|
| gemini-2.5-flash (기본) | 10회 | 500회 | **무료** |
| gemini-2.5-pro (고품질) | 5회 | 25회 | **무료** |

### 실제 사용량 시뮬레이션

- **하루 5번 사용 × 30일 = 월 150회** → 무료 한도(500회/일) 안에서 충분히 해결
- 하루 한도를 넘기는 경우는 거의 없을 것이다

### 한도 초과 시

무료 한도를 넘기면 `429 오류`가 뜬다. 그럴 때는:
1. 다음 날(태평양시간 자정 기준) 자동 리셋될 때까지 기다리거나
2. Google AI Studio에서 결제수단 등록 → 유료 전환 (토큰당 과금)

> **당분간은 무료로 충분하다.** 한도가 부족해질 만큼 쓰게 되면 그때 고민해도 늦지 않다.

## 6. 모델 교체하는 법

`⚙ 설정` 모달에서 **모델** 칸을 바꾸고 저장하면 끝. 코드 수정 없음.

사용 가능한 모델 문자열:
- `gemini-2.5-flash` — 균형, 기본값. 하루 500회 무료
- `gemini-2.5-pro` — 고품질, 하루 25회 무료. 복잡한 기획·검수에 권장
- `gemini-2.5-flash-lite` — 가장 빠름, 하루 1,000회 무료. 빠른 발굴에 적합

> **언제 pro로 올리는가?** 정의서의 미묘한 톤 차이가 중요한 검수 작업, 또는 시나리오/스크립트처럼 결이 길게 가야 하는 초안일 때. 일상 발굴은 flash로 충분하다.

## 7. 첫 사이클 테스트 시나리오

비서가 제대로 작동하는지 한 번에 확인하는 방법:

1. **발굴**: "오늘 출근길 지하철에서 졸고 있던 사람의 손에 들린 커피가 안 흘렀다" 같은 한 장면 입력 → 후보 3~5개를 받는다
2. **초안**: 후보 중 하나 골라서 "인스타 캡션" 형식으로 → 본문 + 의도된 감정 경로 + 숨은 따뜻한 착지 한 줄을 받는다
3. **검수**: 받은 캡션을 검수 탭에 붙여넣기 → ✅ ⚠️ 🔧로 정의서 11항목 점검을 받는다

이 1사이클이 매끄러우면 세팅 성공이다. 어딘가 어색하면 — 그게 바로 다음에 정의서나 워크플로우를 손볼 자리다.

## 8. 막히면

- **API 키 오류**: [aistudio.google.com/apikey](https://aistudio.google.com/apikey)에서 키를 다시 복사했는지 확인. `AIza...`로 시작해야 한다
- **429 오류 (한도 초과)**: 하루 무료 한도를 넘긴 것. 다음 날 자동 리셋되거나, gemini-2.5-flash-lite로 모델을 바꿔보기
- **config 안 읽힘**: GitHub Pages가 빌드 끝났는지 1~2분 기다려보기 / `⚙ → config 새로고침`
- **응답이 GGHN답지 않음**: `config/system-prompt.md` 또는 워크플로우 파일 손보기. 정의서가 답한다
- **로그가 안 쌓임**: 다운받은 log.json을 GitHub의 `memory/log.json`에 덮어쓰는 단계를 빠뜨렸을 가능성
